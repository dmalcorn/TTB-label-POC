## 2026-06-12 — Source extraction (subagents)

**Captured as DECIDED (from PRD + ux-design-notes, high confidence):**

- **Form-factor:** Browser-based web app, server-side compute (CPU-only, no local disk). Tuned for large monitors — min 24", typical 27" or dual-24. Not mobile/tablet.
- **UI system:** USWDS (U.S. Web Design System), fully self-hosted/vendored — no CDN or outbound asset calls (firewall constraint). Both spines inherit USWDS tokens & components; specify behavioral/visual deltas only.
- **IA (surfaces):**
  - *Token gate* — lightweight access, no login ceremony, clean denial.
  - *Queue / "Get Next" screen* — single primary action **Next Submission**; optional type filter (Wine/Spirits/Beer); informational stats strip. No list browsing.
  - *Review Workspace* — the heart. Left = label image(s) + enhance controls; right = vertically stacked field comparison + smart checklist; top = beverage-type banner + chevron step indicator + advisory verdict; bottom = Notes + Disposition action bar.
  - *Help panel* — persistent `[?]` in header, one-click, searchable, local KB.
  - *Benchmark Report* — evaluator-only; engines/models side-by-side (speed/accuracy/cost). [SCOPE Q — see below]
  - *Operational* — demo reset, fixture enqueue (not specialist-facing).
- **Load-bearing distinction (P4):** Engine **Verdict** (PASS/REVIEW/FAIL — advisory, muted Tag/Alert register, labeled "Suggested:") is visually separate from human **Disposition** (Approved / Needs Correction / Rejected — full-saturation Buttons in bottom action bar). Engine never pre-selects disposition.
- **Core interaction — vertical stacked field comparison:** Application value above OCR value (not side-by-side; avoids wide-monitor eye travel). Matches = quiet (thin border + green ✓ chip). Mismatches = thick left border + tinted fill + **character-level diff** on the differing span. Normalized/soft mismatch (e.g., "STONE'S THROW" vs "Stone's Throw") = distinct **amber "check"** state with plain-language explanation, never red. Mismatches float to top; matches sink.
- **Government Warning** rendered as "Required (27 CFR §16.21) vs On-label" comparison — compares to the *regulation*, deterministic.
- **Beverage-type banner:** full-width, large word + icon + accent. Spirits = amber/brown, Wine = burgundy, Beer = gold. Word always present; color is reinforcement.
- **Chevron status bar (USWDS Step Indicator):** ① Identity → ② Mandatory text → ③ Gov. Warning → ④ Conditional → ⑤ Decide. Orientation/progress map, NOT a wizard (single page; clicking a step scrolls).
- **Smart pre-checked checklist:** generated from ruleset per beverage type; engine pre-ticks auto-verifiable PASS items (muted), leaves REVIEW/FAIL for human; clicking an item scrolls to its field card; "N of M done" counter; soft-gate confirm modal if approving with open REVIEW items.
- **Accessibility floor:** every status = color + icon + word (never color alone); body ≥16px, comparison values 18–20px; targets ≥48px; keyboard power path (N=Next, A/C/R=dispositions, arrows for image faces); no work-losing timeouts; calm-by-default (only problems draw the eye). USWDS gives 508/WCAG AA baseline; full 508 audit out of POC scope.
- **Tone/voice:** calm, authoritative, not alarming; plain language ("Send back for correction," not status codes) per Plain Writing Act.
- **Personas/journeys:** Dave (28-yr veteran, low-tech, adoption gate — single big button, mouse-only sufficient); Jenny (8 months, keyboard power path, wants checklist in software); + Evaluator (procurement/benchmark). ~5s readiness is the product identity (enabled by background pre-compute; UI never blocks).

## 2026-06-12 — Finalize: validation + mocks

**Validation:** 3 parallel lenses ran — rubric walker, accessibility (508/WCAG AA), edge-case hunter. Reports: `review-rubric.md`, `review-accessibility.md`, `review-edge-cases.md`; consolidated in `validation-report.html` / `.md`. Rubric verdict: strong/ship-ready as a downstream contract.

**Findings resolved in the spines (this run):**
- **[critical] Contrast** — verdict foregrounds darkened to clear AA on their tints: `pass #2E8540 → #216E29`, `review #B8860B → #7A5900` (also makes the soft-card amber left bar clear the 3:1 graphic floor and incidentally splits review from the beer-gold hex). Added an explicit DESIGN.md **Contrast table** for all domain combos; softened the over-claiming "verified to hold ratios" line; recorded the beer-banner dark-ink-only constraint.
- **[critical] Verdict roll-up rule** — stated precedence (any FAIL→FAIL, else any REVIEW/can't-verify→REVIEW, else PASS) on the Suggested-verdict Alert.
- **[critical] Undo / persist-failure** — added "Recorded — Undo" affordance + finality note; added save-failure State Pattern (stays on Review, retains Notes/ticks, honest retry); disposition bar disables on submit (double-submit guard).
- **[high] Accessibility under-spec** — keyboard-shortcut safety (inert in text inputs / modals; buttons are canonical SR path); aria-live for post-load changes (N-of-M, roll-up, Enhance, LLM notice); character-diff text equivalent + forced-colors survival; modal/Help focus trap + return; Notes validation accessibility; tick-state survives full reload; chevron current-step non-color marker.
- **[high] Edge states** — Gov Warning total-absence (NOT_FOUND ≠ diff); field NOT_FOUND vs mismatch; OCR-unreadable field (REVIEW); blank application value; cold-start (items processing ≠ empty); demo-reset-while-open; Enhance omitted on clean photo; image-decode-failure placeholder; 0/10-image bounds; all-REVIEW copy; chevron step-④ clean renumber; Benchmark no-data state; Help no-results state; single-user POC stated in Foundation.

**Accepted / not changed (low, defensible):** Flow 3 has no failure beat (evaluator walk-through, no user-error branch); minor Foundation↔DESIGN form-factor restatement (each spine is self-contained); token-expiry-mid-session and multi-image OCR-candidate-selection (Phase-2 / engine-detail, noted in edge report, not blocking); banner letter-spacing (cosmetic). Match-card 1px border stays decorative — the ✓ chip + word carry the state.

**Mocks (5, offline HTML, in `mockups/`):** `token-gate.html`, `queue.html`, `review-workspace.html` (hero — DISTILLED SPIRITS/REVIEW), `help-panel.html`, `benchmark-report.html`. Linked inline in both spines; spines win on conflict.
