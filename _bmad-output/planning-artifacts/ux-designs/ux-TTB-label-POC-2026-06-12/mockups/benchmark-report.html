OCR & LLM Benchmark Report

Evaluator view · read-only

This is a procurement study, not a live control. It lays the candidate OCR engines and language models side by side on the four things that decide the buy: field-level accuracy, latency, cost per 1,000 verifications, and whether each can run CPU-only inside the firewall. Nothing here records a decision — it's here so you can compare the options on the same footing.

✓Recommendations

  • OCR baseline: PaddleOCR (PP-OCRv5). Highest field accuracy of the CPU-only engines and fast enough for the ~5s readiness budget; Tesseract stays as a zero-dependency fallback.
  • Language model for the judgment checks: Claude. Best accuracy on the soft/normalized comparisons (capitalization, wording) at acceptable latency; the screen still works OCR-only if the model is config-off or unreachable.
  • Keep the deterministic checks deterministic. The Government Warning (27 CFR §16.21) is an exact text compare — it does not depend on a model and stays out of the LLM cost line entirely.

⚠How to read these numbers
These figures are indicative, not audited. Honesty is a feature here, so the caveats are stated plainly rather than buried:
  • Accuracy and latency come from a seeded fixture set of sample labels, not the full production corpus — treat them as illustrative ballparks for comparison, not guarantees.
  • For the language models, published API prices stand in for internal model cost — we don't host these models, so the list price is the closest honest proxy we have.
  • The OCR engines are self-hosted and vendored, so their per-1,000 cost is compute only and shown as $0.00 in this study (no per-call charge).
  • Latency is per item on CPU-only reference hardware; the ~5s readiness budget is met by pre-computing in the background, so model latency does not block the specialist.
